# アプリの役割分担と整理計画

## 現状

- 実際のVite入口は`src/main.tsx`から`AcousticLab`を直接起動している。一方、`src/App.tsx`には入口から参照されない3Dスピーカー表示が置かれ、package名も`my-vue-app`のまま。
- `AcousticLab`にはAVR操作、結果確認、ローカルブラウザー録音、履歴が同居している。MacのSwiftターゲットにはAVR接続・クラウド処理とCoreAudio録音がある。
- tvOSはペアリング済み素材をAVPlayerで受け取り再生する。iOS専用アプリはまだない。

## 目標

| アプリ | 担当 | 収録・再生の境界 |
| --- | --- | --- |
| Webブラウザー | AVR制御、測定条件、結果・履歴・位置比較、補正案、iOSアプリとtvOSの指示 | Mac内蔵マイクを計測器として扱わない。操作画面から再生を勝手に開始しない |
| iOSアプリ | 同じWeb操作画面を表示し、iPhone/iPadまたは接続マイクでPCMを収録 | iOSのマイク権限・入力経路・処理状態・サンプルレートを記録。画面遷移やバックグラウンド移行で収録を安全に停止 |
| tvOSアプリ | 選択・承認された検証素材を再生 | Stereo、対応するマルチチャンネル素材、Dolby Atmos対応素材を区別。AVRのAtmos表示だけで14chの分離を認定しない |
| Mac補助プロセス | ネットワーク内AVRの接続、クラウド測定ワーカー、診断 | マイク録音を担当させない。既存Macワーカーはクラウド互換用として維持し、音を再生しない |

## 実装順

1. **入口の整理:** Webの起動点を`src/App.tsx`へ一本化し、3Dスピーカー表示を配置ビューとして明示的な別画面へ移す。実際の入口から外れていた表示を削除せず、アプリ内で見つけられるようにする。package名もプロジェクト名に合わせる。
2. **機能境界:** WebのAVR・結果・調整画面、iOS収録ホスト、tvOS再生エンドポイント、Macネットワーク補助の責任とデータ契約を固定する。既存IndexedDB/クラウドの保存形式を移行しない。
3. **iOSホスト:** 新しいSwiftUI/WKWebViewアプリから同じHTTPS Web UIを開く。マイク許可をネイティブで取得し、Webの録音経路を使う。USBオーディオインターフェースは実機で認識・入力・レートを確認してから対応表示する。
4. **tvOSソース選択:** 素材manifestに形式・レイアウト・検証状況を記録し、Stereo / Multi Ch In / Dolby Atmosを画面で明示。対応コンテナとAVR経路を検証し、未検証素材は通常測定に使わない。
5. **Mac録音の撤去:** iOS経路が保存・中断・再解析まで利用可能になってから、Macローカル録音UIと重複処理を外す。MacのAVR/worker機能とクラウド互換測定は維持する。

## Mac内蔵マイクの周波数について

「ヒンジ音対策で特定周波数が常時カットされる」という説明は、現時点の情報からは断定できない。AppleのMic ModeはStandard以外で内蔵マイク・外部入力の音を変えることがあり、Voice Isolationは周囲音を抑える。[Appleの録音向け案内](https://support.apple.com/en-la/121587)はMacの入力音がMic Modeによって変わると説明している。ブラウザーがAEC/AGC/NSを無効に要求した事実だけではmacOS側処理停止の証明にならない。計測時はアプリ別Mic ModeをStandardにし、選択入力、トラック報告レート、実測スペクトルを確認する。

iPhone側も「内蔵マイクなら無処理」とはみなさない。Appleは対応機器の内蔵マイク群とbeamforming入力を説明し、対応アプリではWide Spectrumが収録時の処理を減らすとしている ([内蔵マイク入力](https://developer.apple.com/documentation/avfaudio/capturing-stereo-audio-from-built-in-microphones)、[iPhoneのMic Mode](https://support.apple.com/en-my/101993))。このWKWebViewアプリはiOSのMic Modeを直接固定しない。収録前にControl Centerのアプリ別Mic Modeが表示されるか確認し、Wide Spectrumを選べる場合は選んで、Web側が報告するAEC/AGC/NSと入力経路も確認する。

今回のUR12確認では2入力を認識し、10秒のPCM収録を保存できたが、信号レベルはピーク−82.96 dBFS、RMS−96.46 dBFSだった。マイクの周波数応答・音響校正・ノイズ処理停止を検証した結果ではない。夜間のため実スピーカーを使う試験は行わない。

## この整理で実装したことと保留

- Web入口を一本化し、配置ビューを`/visualizer`に分離。入口に無かった3D表示も残し、測定画面から移動できる。
- iOSのSwiftUI/WKWebViewアプリを追加。HTTPSでWeb画面を開き、許可した同一オリジンだけでマイク収録を許可する。Web画面のPCM保存・解析を使う。iOSシミュレーター向けビルド成功。配布先URL、実機マイク経路、UR12接続は未確認。
- tvOSのAVPlayer再生・登録済み素材検証は既存経路を維持。素材登録にStereo / Multi Ch In / Atmosの形式を追加し、その形式を検証記録とTVの準備表示で照合する。実機出力の検証は未実施。
- 通常のMacブラウザーではローカル収録・マイク入力列挙・再生開始を表示しない。収録入口はiOSアプリがホストするWebViewだけに表示する。iOSのWebView収録結果はクラウドへ同期し、Macブラウザーの解析・履歴へ反映する。
- Mac側の既存クラウド解析ワーカーは互換用として残す。実機出力による音響試験は行わない。

## 完了条件

- Webの各画面が一つのアプリ入口から明示的に開け、重複・未使用の入口を残さない。
- iOSが録音を前面・ローカル保存で行い、権限拒否、入力変更、割込み、バックグラウンド移行を安全に扱う。
- tvOSで形式とチャンネルレイアウトが表示され、Stereo、対応Multi Ch、Atmos素材の検証状態を混同しない。
- 実機出力を使わない自動検証を行い、スピーカーから音を出す確認はユーザーが実施可能な時間に別途行う。
