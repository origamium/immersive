# Acoustic Lab: 測定方式と能力の境界

## 対象環境

- Mac: M3 Max MacBook Pro。ユーザー申告はmacOS 26.6.2。ビルド検証にはインストール済みXcodeの26.5 SDKを使用。
- iPhone 17 Pro Max / iOS 26.6.2: ユーザー申告。実機の入力処理・時刻精度・USBマイクの動作は未検証。
- Apple TV 4K: 世代・tvOSの正確なビルドは未確認。端末の能力レポートにOSと音声セッションの実際値を記録する。
- AVC-A110 / PMA-A110 / 7.1.6: 14位置を管理。開発中のMacにはDenon機器が接続されておらず、各スピーカーからの実音は検証していない。

## 再生能力の調査（2026-09-11）

| 経路 | 仕様で確認できる能力 | この実装での扱い |
| --- | --- | --- |
| Mac HDMI → AVC | MacのHDMIは最大8 ch / 24 bit / 192 kHz。AVCのマルチPCMは最大7.1 | CoreAudio AUHALで実際の出力デバイスとレートを指定。要求と実際値が異なれば準備を失敗させる。高さ6本を14 ch PCMとして直接送らない |
| Mac USB → PMA | PMAのMac設定は2 ch / 32 bit integer / 384 kHzを案内 | 2 ch経路として扱う。DACの対応上限と実際に選択できるフォーマットを分ける。Float32の信号生成から32 bit精度やbit-perfectを主張しない |
| Apple TV → AVC | Atmos再生に対応。Apple Musicのロスレスは48 kHz超に非対応 | AVPlayerでローカルに取得済みの素材を再生。任意のネイティブアプリの出力すべてを48 kHz固定と断定しない |
| Safari / Web Audio | AudioContextのレートに合わせた変換がある。ブラウザーの設定値はハードウェアの物理フォーマットではない | iPhone/MacブラウザーはPCM録音端末。ブラウザーをHigh-res bit-perfect出力として扱わない |

Continuous AudioではDolby MAT接続が続き、AVRがAtmosと表示していても実コンテンツのチャンネル構造を証明できない。高さの検証は、対象スピーカー以外への漏れ、AVRのモード、経路、前後マーカーの再現性を記録して行う。

AppleのAPAC/ASAFは空間音声の有力な検証対象だが、ASAF対応・APACエンコード可能という事実から、AVCへ7.1.6を個別出力できるとは推論しない。この版はAPACエンコーダーや有料Atmos制作ツールを同梱しない。[AppleのAPAC/ASAF解説](https://developer.apple.com/videos/play/meet-with-apple/223/)

## 信号と解析

1. 既定−30 dBFS、20 Hz〜20 kHz、10秒の指数スイープ。20 msの端点フェード。設定は−80〜−12 dBFS、1〜30秒に制限。
2. 前後に80 msのチャープを入れる。先頭に1秒、スイープ前に0.5秒、スイープ後に3秒の余白を設ける。共通の基準スピーカーがあれば、そこへ両マーカーを送る。
3. 相互相関で両マーカーを検出し、帯域制限補間でピークの小数時刻を推定。間隔比から独立した再生・収録時計のドリフトを推定する。±1000 ppm以上は拒否。
4. windowed-sincで時計を補正し、正則化した周波数領域の除算でIRを求める。時間基準の前0.25秒、後2.5秒を保持する。マーカーは「音響的な基準」であり、OSやDACの絶対遅延ではない。
5. IRのFFTから1/48オクターブ間隔の応答を作成。ブラウザーの表示平滑化はパワー平均。校正値は対応帯域の応答から差し引き、未対応帯域を明示する。
6. 帯域フィルター後のSchroeder積分でEDT/T20/T30を推定。雑音余裕10 dB、必要な減衰幅、20点以上、回帰R²≥0.95を要求し、不足時は値を出さない。
7. 低域は各時刻から0.5秒の窓を用いた時間別スペクトルも表示。窓による約2 Hzの分解能制約がある。帯域フィルターは研究用のbiquadで、規格準拠オクターブフィルターとして認証していない。

理論背景: [Farinaによる指数スイープ測定法](https://www.angelofarina.it/Public/Papers/134-AES00.PDF)。この実装は線形IRを中心とした解析で、非線形次数の分離・THDの認証済み測定は提供しない。残響時間の規格適合を主張しない。小部屋の低域を単一のRT60で評価しない。

## 品質と提案

- クリップ、PCMの欠落、録音の中断、ハッシュ不一致、マーカー欠落、SNR不足を有効な調整データにしない。
- AGC/NS/AECを無効に要求し、ブラウザーが返した値を保存する。返却値は物理DSPの完全な停止の証明ではない。iPhone内蔵マイクは位置・向き・ゲインを揃えた相対評価を基本とする。
- 感度校正オフセットはメタデータとして残すが、正規化された伝達ゲインへ単純加算して絶対SPLと表示しない。
- PEQ候補は品質条件、周波数校正、目標カーブがそろった場合のみ。20〜300 Hz、最大8本、最大−6 dB、Q 0.5〜8。ディップをブーストせず、AVRへ自動書き込みしない。目標カーブのレベル基準は測定と揃える。
- 平均レベル差を除いたRMSで似た応答を探す。条件差を表示し、原因の自動断定は行わない。
- 同一条件の繰り返しは平均と標準偏差で確認。標準偏差は校正誤差を含む精度保証や信頼区間ではない。

## 実機での受け入れ手順

1. 校正済み外部マイクを固定。ファイル、方向、入力ゲイン、アンプ音量、Audyssey / Dynamic EQ / Dynamic Volume / クロスオーバー / 距離を記録。
2. 低い音量で、物理chと画面のマッピングを一本ずつ確認。PMAは2 ch、HDMIは実際の8 ch以下。LFEと低域管理によるサブへの転送を区別する。
3. 同一点で3回測定し、雑音・クリップ・時計ずれと標準偏差を確認。iPhoneでは画面を前面に保つ。
4. 測定点を複数に増やし、低域ピークが位置に伴ってどう変わるかを比較する。寸法からの定在波予測は仮説として照合する。
5. Apple TVはまず検証モードで素材を確認。マーカー、対象chの分離、接続経路を記録して通常測定を有効化。経路・設定変更時は再検証。
6. REW等の独立した測定と同条件で比較する。現時点では実機REWとの一致試験は未実施。
7. 一度に一つだけ配置・吸音・設定を変え、同じプロファイルで再測定し、改善ログへ聴感も残す。
